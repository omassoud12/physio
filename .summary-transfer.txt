======================================================================
2. PROJECT OVERVIEW
======================================================================

PhysioCare Clinic is a website for managing a physiotherapy clinic.

The system has:

- A public clinic website.
- Patient registration and sign-in.
- A separate dashboard for patients.
- A separate dashboard for physiotherapists.
- A separate dashboard for the administrator.
- An appointment calendar.
- Doctor working-hours and time-off management.
- Automatic doctor assignment when a patient does not choose a doctor.
- Gender-aware doctor matching.
- Clinic account and patient assignment management.

Main technology:

- Frontend: React and Vite.
- Backend: Node.js and Express.
- Login system: Supabase Auth.
- Database: Supabase PostgreSQL.
- API communication: Axios.
- Security: access tokens, role checks, ownership checks, database
  triggers, and Supabase Row Level Security.

3. USER ROLES
======================================================================

3.1 Patient

A patient can:

- Create a patient account.
- Sign in to the patient dashboard.
- Complete their profile gender if it is missing.
- View doctors who are active and accepting appointments.
- View a monthly calendar of available appointment days.
- View the available times on a selected day.
- Choose a specific physiotherapist.
- Leave the doctor choice open and let the system assign one.
- Enter a treatment type and optional appointment notes.
- Request an appointment.
- See the doctor assigned to the appointment.
- View upcoming pending and confirmed appointments.
- Cancel an upcoming appointment.

A patient cannot:

- Open the physiotherapist dashboard.
- Open the administrator dashboard.
- Manage another patient's appointments.
- Change a doctor schedule.
- Manage clinic accounts.


3.2 Physiotherapist

A physiotherapist can:

- Sign in to the physiotherapist dashboard.
- View today's schedule and upcoming appointments.
- Confirm or reject a pending appointment.
- Mark a confirmed appointment as completed or no-show.
- View only patients connected to them through an assignment or
  appointment.
- Edit their professional profile.
- Choose whether they are accepting new patients.
- Add weekly working periods.
- Edit, pause, enable, or remove weekly working periods.
- Choose the length of appointment slots.
- Add or remove time-off exceptions.

A physiotherapist cannot:

- Open the patient dashboard as a patient.
- Open the administrator dashboard.
- View another physiotherapist's private appointment list.
- Change another physiotherapist's working hours.
- Manage unrelated patient records.
- Change their own gender or license number. The administrator manages
  those fields.


3.3 Administrator

The administrator can:

- Sign in to the administrator dashboard.
- View clinic totals and pending appointment totals.
- Search and view patients.
- Enable or disable patient accounts.
- Create physiotherapist accounts.
- View and manage physiotherapist accounts.
- Enable or disable physiotherapist accounts.
- Set or correct a physiotherapist's gender.
- Create a patient-to-physiotherapist assignment.
- End an active assignment while keeping its history.

The current database design allows one active administrator account.

4. WEBSITE PAGES

4.1 Home Page

Access: Everyone

Access: Everyone

Purpose:

Address: /register
Access: Everyone

- Checks that both password fields match.

Purpose:

- Tests the frontend, backend, and Supabase connection.

This is mainly a development and troubleshooting page.


4.5 Patient Dashboard
Address: /patient/dashboard
Access: Patients only

Main booking area:

- Loads the patient's profile and appointment list.
- Asks older patients to add gender if the value is missing.
- Displays an appointment calendar for the selected month.
- Marks days that have available appointment times.
- Displays time buttons for the selected day.
- Shows the number of available doctors for each time when the patient
  selects "Any available physiotherapist."
- Lets the patient filter the calendar by one doctor.
- Lets the patient enter a treatment type and optional notes.
- Requests the appointment from the backend.
- Shows the assigned doctor's name after a successful booking.
- Refreshes the calendar if another patient takes the time first.

Upcoming appointments:

- Shows pending and confirmed future appointments.
- Displays the treatment type, doctor, date, time, and status.
- Lets the patient cancel an active upcoming appointment.

Doctor directory:

- Shows eligible doctors returned by the backend.
- Displays each doctor's name, title, specialization, biography,
  experience, and normal consultation length.
- Lets the patient select a doctor card and filter the calendar.

Gender rule:

- A female patient only sees female physiotherapists.
- This is not only a visual frontend filter.
- The backend, database trigger, and database security policies also
  enforce the rule.

Time rule:

- Calendar and appointment times are currently handled and shown in UTC.


4.6 Physiotherapist Dashboard
Address: /physiotherapist/dashboard
Access: Physiotherapists only

The dashboard has five tabs.

Schedule tab:

- Shows the number of appointments today.
- Shows the number of upcoming active appointments.
- Shows the number of authorized patients.
- Displays today's visits or the next upcoming visits.

Appointments tab:

- Shows only appointments booked with the signed-in physiotherapist.
- Lets the physiotherapist confirm or reject pending appointments.
- Lets the physiotherapist complete a confirmed appointment.
- Lets the physiotherapist mark a confirmed appointment as no-show.

Patients tab:

- Shows patients assigned to the physiotherapist.
- Also shows patients who have an appointment with the physiotherapist.
- Displays limited patient contact and medical-record information.

Availability tab:

- Shows Monday through Sunday in the correct order.
- Lets the physiotherapist add more than one working period on a day.
- Lets the physiotherapist edit the day, start time, end time, and slot
  length.
- Lets the physiotherapist pause or enable a working period.
- Lets the physiotherapist save or remove a working period.
- Prevents invalid times and overlapping active periods.
- Lets the physiotherapist block time for holidays, training, or personal
  leave.
- Lets the physiotherapist remove a time-off block.
- Uses UTC as the clinic scheduling time.

Profile tab:

- Lets the physiotherapist update their first name, last name, and phone.
- Lets the physiotherapist update professional title and specialization.
- Lets the physiotherapist update biography and years of experience.
- Lets the physiotherapist update consultation length and profile image.
- Lets the physiotherapist choose whether they are accepting patients.
- The public doctor directory uses this information.


4.7 Administrator Dashboard

Access: Administrators only

The dashboard has four tabs.

Overview tab:

- Shows total active patients.
- Shows total active physiotherapists.
- Shows total appointments.

- Shows each physiotherapist's gender.

- Shows active patient-to-physiotherapist assignments.

======================================================================
5. MAIN SYSTEM WORKFLOWS
======================================================================

5.1 Sign-In and Role Protection

1. The user enters an email and password.
2. Supabase checks the credentials.
3. The backend loads the user's current active profile.
4. The frontend saves the session and profile in browser storage.
5. The user is sent to the correct dashboard.
6. Every protected API request includes the access token.
7. The backend checks the token again and reloads the profile.
8. The backend checks the user's role before allowing the action.
9. If the session expires, the frontend clears it and returns to Sign In.


5.2 Doctor Availability

1. A physiotherapist adds recurring weekly working periods.
2. Every period has a weekday, start time, end time, and slot length.
3. The system prevents active periods for the same doctor from
   overlapping.
4. The physiotherapist can pause a period without deleting it.
5. The physiotherapist can add time off for a specific date and time.
6. The booking service generates appointment slots from active periods.
7. Past times are removed.
8. Time-off periods are removed.
9. Times used by pending or confirmed appointments are removed.


5.3 Patient Calendar

1. The patient opens the monthly calendar.
2. The frontend asks the backend for a date range.
3. The backend finds doctors who are active and accepting patients.
4. The backend applies the patient's gender-matching rule.
5. The backend generates free slots from doctor working hours.
6. Times offered by more than one doctor are grouped together.
7. The calendar marks days with at least one available time.
8. The patient selects a day and then a time.

The calendar API accepts a range of up to 42 days.


5.4 Booking a Specific Doctor

1. The patient chooses a physiotherapist.
2. The calendar shows only that doctor's available times.
3. The patient selects a time and sends the request.
4. The backend checks the doctor's activity, gender eligibility, working
   hours, time off, and existing appointments again.
5. The backend saves the appointment as pending if the time is still free.
6. If the time was just taken, the patient receives a conflict message and
   the calendar refreshes.


5.5 Automatic Random Doctor Assignment

1. The patient leaves the doctor selector on "Any available
   physiotherapist."
2. The patient selects a time.
3. The backend finds every eligible doctor free at that exact time.
4. The backend puts those doctors in a random order.
5. The backend tries to create the appointment with one doctor.
6. If another patient took that doctor's slot at the same moment, the
   backend tries another eligible doctor.
7. The backend returns the assigned doctor's name after a successful
   booking.

For a female patient, the eligible list contains female doctors only.


5.6 Appointment Status

New appointments start with the status "pending."

Normal status changes:

- Pending -> Confirmed
- Pending -> Rejected
- Pending -> Cancelled
- Confirmed -> Completed
- Confirmed -> Cancelled
- Confirmed -> No-show

The database keeps an appointment status history.


5.7 Patient and Physiotherapist Assignments

- An administrator can assign one physiotherapist to a patient.
- The database allows one active assignment per patient.
- Ending an assignment marks it inactive and keeps the history.
- A physiotherapist can view a patient's limited details when there is an
  active assignment or appointment relationship.

6. BACKEND AND API
======================================================================

The backend is an Express application.

Main API groups:

Authentication and profile:

- POST /api/auth/signup
- POST /api/auth/signin
- GET /api/profile/me
- PATCH /api/profile/me

Doctor directory and patient booking:

- GET /api/physiotherapists
- GET /api/physiotherapists/:id
- GET /api/physiotherapists/:id/available-slots
- GET /api/appointments/availability
- POST /api/appointments
- GET /api/appointments/my
- PATCH /api/appointments/:id/cancel
- PATCH /api/appointments/:id/reschedule

Note:

- The backend supports patient rescheduling.
- The current patient dashboard does not yet show a reschedule control.

Physiotherapist tools:

- GET and PATCH /api/physiotherapist/me
- GET and POST /api/physiotherapist/availability
- PATCH and DELETE /api/physiotherapist/availability/:id
- GET and POST /api/physiotherapist/time-off
- DELETE /api/physiotherapist/time-off/:id
- GET /api/physiotherapist/appointments
- PATCH /api/physiotherapist/appointments/:id/status
- GET /api/physiotherapist/patients
- GET /api/physiotherapist/patients/:id

Administrator tools:

- GET /api/admin/dashboard
- GET and POST /api/admin/physiotherapists
- PATCH and DELETE /api/admin/physiotherapists/:id
- GET /api/admin/patients
- GET, PATCH, and DELETE /api/admin/patients/:id
- GET and POST /api/admin/patient-assignments
- PATCH and DELETE /api/admin/patient-assignments/:id

Connection test:

- GET /api/test

7. DATABASE INFORMATION
======================================================================

Important database tables:

profiles:

- Stores the basic account profile.
- Includes name, email, phone, gender, role, and active status.
- Patient medical information can include date of birth and medical record
  number.

physiotherapists:

- Stores professional information for physiotherapist accounts.
- Includes title, license number, specialization, biography, experience,
  normal consultation length, image, and accepting-patients status.

physiotherapist_working_hours:

- Stores recurring weekly working periods.
- Includes weekday, start time, end time, slot length, and active status.

physiotherapist_time_off:

- Stores one-time unavailable periods and an optional reason.

appointments:

- Stores patient, doctor, treatment type, start and end times, notes, and
  appointment status.
- Prevents two active appointments from using overlapping time for the
  same doctor.

appointment_status_history:

- Stores appointment status changes and the user who made each change.

patient_physiotherapist_assignments:

- Stores active and past care assignments.
- Keeps the administrator who created the assignment and the assignment
  dates.

8. SECURITY AND PRIVACY RULES
======================================================================

- Passwords are managed by Supabase Auth.
- Passwords are not stored in the project files or normal database tables.
- The Supabase service secret belongs only in the backend environment.
- The frontend must never receive the service secret.
- Protected endpoints require a valid access token.
- The backend reloads the account profile for every protected request.
- Disabled users cannot continue using protected API features.
- Role middleware blocks users from other role areas.
- Patient appointment actions are limited to that patient.
- Physiotherapist actions are limited to that physiotherapist.
- Physiotherapists only see related patients.
- Database Row Level Security adds another layer of separation.
- Database triggers check important role and appointment relationships.
- Female patients are limited to female doctors in directory reads and
  booking.
- Disabling an account keeps clinical and appointment history.

10. INSTALLATION AND LOCAL RUNNING
======================================================================

10.1 Database migrations

Run these files in the Supabase SQL editor in this order:

1. supabase/migrations/202607210001_create_profiles.sql
2. supabase/migrations/202607220001_clinic_management.sql
3. supabase/migrations/202607220002_replace_administrator.sql
4. supabase/migrations/202607220003_reconcile_physiotherapist_schema.sql
5. supabase/migrations/202607230001_gender_aware_booking.sql

Important:

- Existing profiles keep an empty gender after the gender migration.
- Older patients are asked to complete gender on their dashboard.
- The administrator can set missing physiotherapist genders.
- Confirm that the configured administrator Auth user exists before
  running the administrator replacement migration.


10.2 Backend environment

Create backend/.env with:

PORT=5000
FRONTEND_URL=http://localhost:5173
SUPABASE_URL=your Supabase project URL
SUPABASE_PUBLISHABLE_KEY=your publishable key
SUPABASE_SERVICE_ROLE_KEY=your backend-only service key
ADMIN_EMAIL=the administrator email

A newer SUPABASE_SECRET_KEY can be used instead of
SUPABASE_SERVICE_ROLE_KEY.


10.3 Frontend environment

Create frontend/.env with:

VITE_API_URL=http://localhost:5000/api


10.4 Install and run

From the main project folder:

npm install
npm run install-all
npm run dev

Default local addresses:

- Frontend: http://localhost:5173
- Backend: http://localhost:5000


10.5 Checks

Backend tests:

npm test --prefix backend

Frontend code check:

npm run lint --prefix frontend

Frontend production build:

npm run build --prefix frontend

11. CURRENT IMPORTANT RULES AND KNOWN LIMITATIONS
======================================================================

- All clinic schedule and appointment times are currently shown in UTC.
- New patient and physiotherapist profiles use "female" or "male" as the
  accepted gender values.
- Older profiles can have no gender until they are completed.
- Female patients only see and book female physiotherapists.
- A doctor must be active, accepting patients, working at the selected
  time, not on time off, and not already booked.
- The forgot-password page has not been built yet.
- The backend supports rescheduling, but the current patient dashboard has
  no reschedule button.
- The female-patient rule is enforced for doctor display and appointment
  booking. The separate administrator assignment tool does not currently
  stop an administrator from assigning a female patient to a male doctor.
- The database prevents a doctor from having overlapping active
  appointments. It does not currently stop one patient from booking
  overlapping appointments with different doctors.
- The Express API performs the full working-hours, time-off, and
  appointment-status checks. Direct Supabase access is restricted by Row
  Level Security, but it does not repeat every calendar rule from the API.
- The Connection Test page is a developer utility, not a normal patient
  workflow.
- This project summary is stored outside the source repository in the
  Desktop "summery project" folder.
